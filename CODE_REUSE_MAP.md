# PRISM-rPPG code reuse map

## Audit scope and permissions

Reference root is `reference_code/prism-rppg/` at `76ae9456d460153c80ed3cab8b15bc5c3f7d3fb3`. Paths below are relative to that root. The static audit covered the 109-file tracked tree, both Python inference packages, backend and worker entry points, frontend integration, dependency and deployment files, and local Git history for assets. Runtime inference and dependency compatibility remain untested.

The checkout has no standalone license. The PRISM README describes research and evaluation use, leaves license terms pending, and flags possible institutional and invention-disclosure restrictions. Treat PRISM-specific source and assets as reference material pending written permission covering the intended use, copying, adaptation, and any distribution. [PRISM README](https://github.com/yash-rai-93/prism-rppg#-confidentiality-notice)

Open-rPPG publishes its upstream tools and source under MIT, with a separate notice directing users to original authors' terms for pretrained models and configurations. For actual code reuse, pin the original upstream revision, verify provenance and applicability to the selected files, and retain the license and copyright notice. PRISM-specific changes require separate clearance. For each detector, specialist, and AU asset, record its own source, terms and checksum. [Open-rPPG license](https://github.com/KegangWangCCNU/open-rppg/blob/main/LICENSE)

### Neural runner issues to resolve before integration

- `Model.update_frame` submits a lambda that reads the mutable frame counter when it runs. Bind the counter at submission. The runner chooses the first detection, can retain stale boxes and drop samples, and can send empty crops to resize. Clip boxes, perform identity association, and propagate an explicit validity mask. Use that mask instead of multiplying output samples by zero.
- `Model.update_face_resized` duplicates source timestamps during fill and skips some input frames. `process_video` assumes usable `frame.time`; its FPS diagnostic computes the reciprocal of timestamp differences without guarding repeats. Retain source timestamps and output-grid timestamps separately, bound interpolation, and handle missing or nonmonotonic timestamps explicitly.
- `Model.__enter__` resets buffers but retains prior inference state, including across videos. It always loads a detector even for `process_faces_tensor`. Initialize model state per clip, make detection optional for pre-cropped input, and make worker exceptions observable. A short clip that only reaches the padded-tail branch increments the signal count without creating the initial signal buffer. Validate output length and flush behavior, and ensure both executors and the video container close on failure.
- `Model.collect_signals` can include a sample before the requested start and uses an inclusive end. Replace slicing with explicit half-open time windows and matching signal/timestamp lengths. `Model.bvp(raw=True)` can still integrate and detrend cumulative-output models. Define raw model output and processed waveform separately.

## Project components to build

| Component | Required implementation |
| --- | --- |
| Facial action units | Versioned AU backend adapter, intensity and presence fields, confidence and missingness, and association with the same face track used for rPPG. BlazeFace keypoints supply geometry. |
| Temporal alignment | Original presentation timestamps and frame indices, target face identity, a gap-aware uniform rPPG grid, half-open shared windows, modality coverage, and observation masks. |
| Multimodal fusion | Per-window branch features, early concatenation, validation-calibrated late fusion, and missing-branch handling. RhythmMamba's `Fusion_Stem` operates within its RGB video model. |
| Deepfake classification | Labeled manifests and source-grouped splits, unimodal and quality-only baselines, fused training, video-level aggregation, threshold selection, metrics and reproducible experiment records. |

Start with one authorized video and a local decoder → face track → forehead and cheek RGB → green and POS → bandpass → BVP, timestamps, masks and quality. Verify the signal with an injected-pulse fixture and inspect one real clip. Then build the labeled manifest and grouped splits, integrate AU extraction, validate alignment, and compare unimodal and fused classifiers. See [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for acceptance criteria.
