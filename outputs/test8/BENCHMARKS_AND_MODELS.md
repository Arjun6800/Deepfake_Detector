# Physiological benchmarks and model feasibility

## Validation data

| Dataset | Reference and protocol | Role in validation |
| --- | --- | --- |
| PURE | Timestamped RGB and finger pulse oximetry. Sixty recordings from ten participants across stillness, talking, translation and rotation. | Compare motion robustness on paired conditions. Request access through the provider. [Original paper and protocol](https://www.tu-ilmenau.de/fileadmin/Bereiche/IA/neurob/Publikationen/conferences_nat/2014/Stricker-FWS-2014.pdf) |
| UBFC-rPPG | 30 fps, 640 × 480 uncompressed video and CMS50E reference waveforms. Forty-two recordings in the realistic subset with variable indoor illumination and a timed task. | Independent check of pulse recovery and coverage under natural changes in rate and light. [Dataset provider](https://sites.google.com/view/ybenezeth/ubfcrppg) |
| COHFACE | 160 one-minute sequences from 40 participants, 20 fps video plus synchronized contact BVP and respiration. | Primary compressed-video transfer check. Include the lighting conditions and keep subjects grouped. [Idiap dataset and access](https://www.idiap.ch/en/dataset/cohface) |

Freeze methods before evaluation. Align video and contact PPG independently by timestamp, document recording offsets and reject invalid contact segments. Report reference-based pulse MAE and coverage together, plus lag-tolerant waveform correlation and known-frequency SNR on valid support. Compare source video with controlled H.264 encodes generated from the same benchmark footage. Keep class labels out of any quality calibration. The local experiments contain synthetic reference frequencies only. None of these benchmark datasets were downloaded.

## Neural rPPG

| Model | Implementation and weights | Hardware, Python and speed | Fit for the current videos |
| --- | --- | --- | --- |
| DeepPhys | Original authors publish the architecture and normalized frame differences. The UW toolbox contains a DeepPhys implementation and training example. An original-author checkpoint or a downloadable DeepPhys checkpoint with clear model-specific terms was not verified. | Compact 2D streams make a CPU trial plausible. Throughput on this machine is unmeasured. The toolbox setup pins Python 3.8 and CUDA PyTorch; its setup is unsuitable for the current Python 3.13 Windows environment as written. | Compression has been directly studied with DeepPhys. The treatment of train-time compression matters, so assess transfer using synchronized references. [Paper](https://openaccess.thecvf.com/content_ECCV_2018/html/Weixuan_Chen_DeepPhys_Video-Based_Physiological_ECCV_2018_paper.html), [toolbox](https://github.com/ubicomplab/rPPG-Toolbox), [compression study](https://pmc.ncbi.nlm.nih.gov/articles/PMC7899506/) |
| PhysNet | Author repository provides the 128-frame encoder–decoder and an MIT license file. The README separately states research-only use. No official checkpoint link was found there. The third-party Open-rPPG model zoo lists PhysNet. | 3D convolution requires clip buffering and more activation memory than frame-wise processing. Start GPU profiling if approved. CPU/GPU inference timing and Python 3.13 compatibility of the original repository are unverified. | Temporal modeling could help with nuisance variation. It requires clean cadence and a matched crop protocol. Verify accuracy under compression and clip fragmentation. [Author repository](https://github.com/ZitongYu/PhysNet), [paper](https://arxiv.org/abs/1905.02419), [Open-rPPG](https://github.com/KegangWangCCNU/open-rppg#model-zoo) |
| EfficientPhys | The author-affiliated UW toolbox publishes the CNN implementation. Open-rPPG offers this architecture in its pretrained model zoo. Confirm the exact weight, data provenance and applicable terms before use. | Authors report 40 ms/frame for C and T2 and 300 ms/frame for T1 on Raspberry Pi 4B. The toolbox pins Python 3.8 and CUDA PyTorch. The third-party JAX route documents Python 3.9–3.13 with Linux CUDA acceleration. | First neural candidate for a controlled throughput trial. Published speed is platform-specific. Compression transfer remains unmeasured here. [Paper, Table 4](https://openaccess.thecvf.com/content/WACV2023/papers/Liu_EfficientPhys_Enabling_Simple_Fast_and_Accurate_Camera-Based_Cardiac_Measurement_WACV_2023_paper.pdf), [toolbox source](https://github.com/ubicomplab/rPPG-Toolbox/blob/main/neural_methods/model/EfficientPhys.py), [Open-rPPG](https://github.com/KegangWangCCNU/open-rppg#model-zoo) |
| PhysFormer | MIT-licensed author repository links a VIPL-HR fold-1 checkpoint and a single-sample inference script. Verify separate checkpoint and training-data terms before relying on code licensing. Open-rPPG also lists an implementation. | Author recipe uses PyTorch 1.9 and imgaug with clip-based inference. Use a separate compatible environment and budget for GPU profiling. Native Windows Python 3.13 and local inference speed are unverified. | A comparison candidate after a lighter model. Test sensitivity to window length, crop and timing, and evaluate compression transfer with contact PPG. [Author repository and checkpoint link](https://github.com/ZitongYu/PhysFormer), [paper](https://arxiv.org/abs/2111.12082), [Open-rPPG](https://github.com/KegangWangCCNU/open-rppg#model-zoo) |

The PhysNet paper reports 0.235 seconds of inference on a 30-second clip for the 64-frame 3D encoder–decoder on Tesla P100. This is a different architecture configuration from the author's 128-frame example. PhysFormer reports training with batch size four on a 32 GB V100 and evaluates 10-second clips. That training setup leaves minimum inference memory and throughput open. [PhysNet paper, inference speed](https://arxiv.org/pdf/1905.02419), [PhysFormer paper, implementation details](https://arxiv.org/pdf/2111.12082)

The available local CPU is an AMD Ryzen 5 7530U. The experiment used Python 3.13.7 and OpenCV 5.1.0. Local neural inference speed, hardware requirements in practice, and compressed-video accuracy remain unmeasured. No model weights or dependencies were downloaded or installed. The toolbox code uses a Responsible AI Source Code License and documents a Linux/macOS setup with WSL guidance. Open-rPPG's code license and model terms are separate.
