# Phase 4.6 benchmark and pretrained model approval brief

**Superseded.** The revised Phase 4.6 uses the existing FaceForensics++ C23 training cohort for signal consistency and action-unit fusion research. The proposed dataset acquisitions are closed. See the [revised results](PHASE46_REPORT.md).

Start with four authorized subjects from **UBFC-rPPG Dataset 2**, one complete recording per subject. Each requires the original **vid.avi** and its matching **ground_truth.txt**, plus the provider’s terms and any synchronization notes. Use an official release manifest to select four subjects in numeric ID order from the eligible set before inspecting video content or pulse quality. Use one recording as an adapter smoke test and all four for a frozen descriptive pilot. The small sample can reveal synchronization and gate failures. Broader conclusions about motion and physiological accuracy require more subjects.

## Implementation after approval

1. Implement a read-only UBFC adapter with per-subject manifests, decoded video timestamps, reference timestamps and explicit time units. Check device and video time origins from release documentation and fixture data. Use timestamp intersection and bounded gap handling. Reject malformed, unsynchronized or inadequate reference intervals. Preserve subject IDs and document dropped windows. Extend to PURE’s native image timestamps and COHFACE’s HDF5 timebase when authorized.
2. Freeze eight-second windows, ROI policy, the 0.35 concentration gate and its existing coverage checks. Reuse GREEN, POS, CHROM, ICA and LGI from the Phase 4.5 path. Compute reference HR independently from contact PPG and cross-check with device HR where available. Report MAE, RMSE, Pearson HR correlation, and both candidate and gated coverage, with counts and participant-level summaries. Report signed and bounded-lag waveform correlations over shared valid samples when alignment and morphology support them. Keep missing, invalid-reference and rejected predictions explicit.
3. Separate quality-gate errors from abstentions. For reference-valid windows with a candidate HR, predefine correct recovery as absolute error at most 5 bpm. Report coverage, positive predictive value, sensitivity and false passes using the existing gate, with descriptive concentration-versus-error plots. Report candidate-missing counts and compare motion/illumination strata without retuning. Treat the four-person results as descriptive.
4. Compare the original frames and paired H.264 copies at fixed CRF values 18, 23 and 35 using the same encoder build, preset, resolution, pixel format and timestamps across encodes. Include a lossless RGB round trip and, where supported, a lossless encode in the same YUV pixel format to distinguish color conversion from quantization. Reuse the exact same pulse reference and time windows. Verify frame counts and timestamp alignment. Record parameters, bitrate and errors. First verify an approved CRF-capable encoder, since FFmpeg and ffprobe were absent from PATH during this review. Export regenerated videos only under permitted terms.
5. Test parsing, time origins, timestamp gaps, reference validity, metrics, gate counts and encode alignment with small local fixtures. Run the full suite and write the physiological validation report under outputs/test9. Preserve Phase 4 and Phase 4.5 artifacts, reference code and existing dataset splits.

This brief follows the findings in the [Phase 4.5 benchmarks report](../test8/BENCHMARKS_AND_MODELS.md). Work is paused at the requested approval checkpoint. Dataset transfers, model weight downloads, environment changes and physiological evaluation have not started.
